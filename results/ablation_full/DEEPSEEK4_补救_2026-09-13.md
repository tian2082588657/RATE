- **问题**：`reduced, single scalar channel` 的 network ROC-AUC **0.778** 是 network 列最高，`RATE*` 的 **0.737** 也被加粗，bold 语义自相矛盾。
- **修复**：统一为「**加粗 = 该列最大值**」（与 Table 4 / Table 5 的既有语义一致）：
  - network ROC-AUC：去掉 RATE* 的 `\mathbf`（0.737），保留 single scalar 的 0.778；
  - network best-F1：把 `$\sum\mu$` 行的 0.103 加粗（列最高），RATE* 的 0.100 去粗；
  - ensemble 两列（0.868 / 0.173）保持加粗，恰为列最高。
  - caption 增补：`Bold marks the maximum of each column, not the configuration the paper reports ... the configuration the paper reports is RATE* (0.737), and we flag the gap between the two rather than suppress it.`
- **顺带**解决问题 11（读者困惑 network 上 single scalar 更高）：caption 已把「列最高 ≠ 论文推荐」写明。

### 2. §5.1 与 Abstract 中 1,190 / 2,063 跨单位相减 ✅

- **修复**：
  - §5.1（新行 ~2219）改为：`The reduced graph's own alert clusters contain 1,190 nodes, but that count lives on the reduced unit and has no unreduced counterpart of the same kind to subtract from it;` 之后直接给 common-unit 的 2,011 vs 2,063，**不再做跨单位减法**。
  - Introduction（贡献/发现段，行 271）同步去掉了「an alert set 42% smaller in reduced-node count」，改为 `a smaller node count inside the alert clusters on the reduced graph`。
  - Abstract 把 `1,190 reduced nodes` 明确为 `1,190 nodes inside the alert clusters **on the reduced graph**`，与后半句的 `original entities` 分单位。
- **效果**：全文不再存在 `42%` 或 1,190↔2,063 的跨单位对比。

## 二、中等程度（4 条，全部已修）

### 4. Table 12 identity 的 Reduce 时间 0.8–1.1 s 无解释 ✅

- **查明**：该列来自 `e6g_cost_profile.py`，identity 路径调 `IdentityOperator(verify=False).reduce(g)`——**返回原图不塌缩的空操作**，0.8–1.1 s 是其调用开销（`ReductResult`/back-map 构建），非 reduction。
- **修复**：caption 增补 `The **id** entry of the Reduce column is the identity operator, which returns the graph unchanged: it is a no-op cost, not a reduction, and is reported so that both paths are timed through the same entry point.`

### 5. Table 5（eqwidth, F1@5/@10）与 Table 6（eqwidth-cu, F1@20）预算不同 ✅

- **修复**：Table 6（`tab:eqwidth-cu`）caption 增补 `The alert column is F1@20, chosen to match the common-unit headline budget of Table 4 rather than the tighter budgets of the width control in Table 5.`

### 6. "Deleting the attack" 实验流程不清 ✅

- **查明**（`e6i_benign_counterfactual.py`）：identity 在**原图**删 GT 节点及其入射边；reduced 用**归约的 node_map** 把 GT 实体映射到归约图节点（**含吸收它的汇总节点**）再删；**两路径都不重跑 reduction**（重跑成本不可接受）。
- **修复**：§4.10 补三句说明删除发生在哪张图、是否需要重新归约、以及由此产生的保守性（`the surviving structure is what the operator produced while the attack was still present ... it measures the pipeline's response to removal of the attack signal, not the response of a reduction that never saw it`）。

### 7. §4.1 训练窗口吸收率 73% vs 测试集 40% 未解释 ✅

- **数据**：训练窗口 22/30 = 73% 被吸收；测试集 54/136 = 40%。
- **修复**：§4.1 增补解释——算子与模板集完全相同，差异来自跨度长度（截断到 4e5 条记录使实体活动集中在被匹配的重复区域；更长的测试分区含更多无模板覆盖的一次性结构）；并说明两者都不是质量论断（被吸收实体仍由其汇总节点代表，common unit 已验证）。
